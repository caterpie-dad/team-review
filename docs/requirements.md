# 팀원 평가 시스템 요구사항 정의

## 목적과 범위
평가자가 제공한 Confluence 루트의 하위 페이지와 GitHub 저장소(또는 조직에 속한 저장소)의 산출물로 개인의 프로젝트 기여를 평가한다. 프로젝트 자체의 성과·가치·등급은 평가하지 않는다. 커밋 수, 코드 줄 수, 문서 수를 점수로 환산하지 않는다. 팀원 간 강제 상대평가나 정규분포를 적용하지 않는다. 결과는 평가자의 최종 검토를 위한 근거 기반 판단 자료이다.

## 사용자 흐름과 수용 조건
1. 설정 파일의 사전 설정 비밀번호로 로그인한다. 미인증 API 접근은 차단한다. 세션 만료·로그아웃·로그인 시도 제한·동일 출처 쓰기 요청 검사를 제공한다.
2. 팀원은 고유 사번/ID, 이름, 여러 GitHub 계정·Confluence 사용자 ID로 관리한다. 중복 계정 귀속은 금지한다. 삭제 대신 비활성화하고 과거 평가에는 팀원 스냅샷을 보존한다.
3. 평가를 만들고 프로젝트 카드에서 이름, 기간, 참여자, Confluence 루트 URL과 GitHub repo/org URL을 지정한다. 선택 칩, 날짜 선택, 가중치 슬라이더를 제공한다. 평가 복제로 반복 입력을 줄인다.
4. 평가 실행에는 프로젝트 가중치의 합 100, 양수 가중치·유효한 기간·참여자·하나 이상의 근거 링크가 필요하다. 서버에서도 검증한다. 초안은 이름·날짜·참여자·링크 미입력과 미완성 가중치를 허용하며, 저장 후에도 입력값을 보존한다. 시작 시 부족한 설정을 한국어 항목명과 프로젝트 순서로 안내하고 실행을 차단한다.
5. 실행 중 설정·팀원·평가 기준을 고정한다. 실행 전후에는 사유를 남기고 편집할 수 있다. 조직은 저장소 목록을 해석해 실행의 범위로 저장한다. 이후 외부 링크·검색·다른 저장소·루트 밖 페이지를 따라가지 않는다.
6. 한 번에 한 평가만 실행한다. 수집/분석 진행률, 현재 작업, 경고, 오류를 표시한다. 취소와 실패/취소 평가 재시도를 지원한다. 프로세스 종료로 중단된 실행은 재시작 때 실패 처리한다.
7. 기간 내 커밋 diff와 Confluence 버전 변경분을 작성자에게 귀속한다. 최신 문서 전체를 마지막 수정자의 실적으로 취급하지 않는다. 계정이 명확히 매핑되지 않으면 미귀속으로 기록한다. 병합 커밋의 중복 변경분·바이너리·생성물은 제외/경고한다.
8. LLM은 고정 기준에 따라 근거 ID·정확한 인용·설명·한계·신뢰도를 포함한 구조화 JSON을 반환한다. 근거 없는 점수, 범위 밖 근거 ID, 잘못된 인용, 잘못된 수치는 서버가 거부한다. 산출물에 포함된 지시문은 데이터로 취급하며 모델은 도구/검색 권한을 갖지 않는다.
9. 팀원 종합 및 프로젝트별 차원 점수와 근거 원문, 작성 시각, 출처, 수집 해시, 신뢰도, 누락 경고를 확인한다. 자료 없는 팀원은 판정 보류한다. 부분 자료는 잠정 평가로 표시한다.
10. 평가자가 각 차원 점수와 평가 의견을 조정할 수 있다. 이유는 필수이다. 원래 LLM 결과와 전후 값·시각을 감사 이력에 보존하고 모든 집계를 즉시 재계산한다. 동시 수정 충돌을 감지한다. 확정된 평가도 사유를 남기고 편집할 수 있으며 저장하면 검토 상태로 돌아간다. 이전 구성과 결과를 감사 이력에 보존한다.
11. JSON/CSV 내보내기, 평가 복제, 초안 삭제, 완료/확정 상태 구분, 운영 설정 상태 확인을 제공한다. 비밀키는 화면/API/오류/내보내기에 포함하지 않는다.
12. Docker Compose 및 한 번의 실행 스크립트, 영속 볼륨, 헬스 체크, 백업/복구 절차를 제공한다. 환경별 URL·인증 방식·토큰·모델·타임아웃·수집 한도를 외부 TOML/환경 변수로 관리한다.

## 기본 평가 기준 (버전 1)
- quality 35%: 정확성, 구조, 유지보수성, 설명의 명확성. 결함과 설계상 장단점을 실제 변경분으로 판단.
- complexity 25%: 해결한 기술적 제약과 문제의 난이도. 장황함이나 변경량을 난이도로 간주하지 않음.
- validation 25%: 테스트·예외 처리·검증 절차·재현성. 문서는 근거 검증과 운영 절차로 판단.
- collaboration 15%: 재사용·인수인계·의사결정 기록·타인이 활용할 수 있는 설명. 외부 평판이나 활동량은 사용하지 않음.
각 차원 0~100: 0~19 심각한 결함, 20~39 개선 필요, 40~59 기본 충족, 60~79 견고함, 80~100 탁월한 완성도. 근거가 없으면 null.

## 집계와 공정성
프로젝트 개인 점수 = 차원별 점수의 기준 가중합(4개 차원 모두 판정 가능한 경우). 보정 전 종합 = 참여 프로젝트의 판정 가능한 점수 × 프로젝트 가중치 / 판정 가능한 참여 프로젝트 가중치 합. 최종 종합 = 보정 전 종합 × 평가 연도 기준 CL 계수. 참여하지 않은 프로젝트는 분모에서 제외. 판정 가능한 가중치/참여 가중치를 coverage로 별도 표시하며 100% 미만은 잠정 결과. 평가 전체 가중합 100과 개인별 참여 분모를 구분해서 화면에 명시한다. 역할·직급·성별·연령 등의 비산출물 특성은 모델에 전달하지 않는다. 귀속 불명·내용 절단·버전/접근 누락은 숨기지 않는다.

## 검증 데이터
2026년 평가, 팀원 10명, 프로젝트 6개(가중치 25/20/20/15/10/10). 복수 GitHub 계정, 문서 버전별 저자, 미매핑 작성자, 기간 밖 자료, 루트 밖 링크, 근거 내 악성 지시, 자료 부족 사례를 포함한다. 모의 LLM은 통신/스키마/집계를 검증하는 결정적 테스트 대역이며 실제 모델의 판단 정확도를 증명하지 않는다. 실제 서비스 연결은 운영 자격 증명으로 별도 검증한다.

## 2026-09-27 변경 요구사항
- GitHub/Confluence ID를 하나씩 추가 버튼/Enter로 등록하고 하단 목록에서 확인·삭제한다. 쉼표 구분 입력과 Git 이메일 등록·귀속을 제거한다.
- 연차 및 기준 연도를 저장하고 평가 연도에 맞춰 연차를 산정한다. 1–8년차 CL2, 9–16년차 CL3, 17년차 이상 CL4.
- 기본 CL 계수는 CL2 1.00 / CL3 0.90 / CL4 0.80이며 외부 설정으로 변경한다. 동일 산출물 점수에서 낮은 CL의 종합점수가 높다. 프로젝트 점수는 산출물 기준을 유지한다.
- 종합 결과에 보정 전 점수·연차·CL·계수를 명시하고 평가 시점의 정책을 보존한다. 기존 평가에는 소급 적용하지 않는다.

## 사후 편집 및 연결 설정 확장
완료 평가의 프로젝트/참여자 추가·삭제·이동, 기간·링크·가중치·평가 내용·비율·의견을 편집한다. 기존 판정과 호환되는 변경은 재집계하고 새 근거/판정이 필요한 항목은 점수 없이 재분석 대상으로 표시한다. 네 평가 기준과 CL 계수를 기본 설정 또는 평가별로 편집한다. 세 서비스 URL·인증을 화면에서 저장하고 각자 연결 테스트한다. 실행 중 공통 설정 변경과 평가 구성 편집은 금지하며 작업 취소/완료 후 수정한다.

## 분석 효율
동일 작성자의 반복 커밋을 검증 가능한 구간별 최종 파일·순변경·중간 변경으로 통합하여 LLM 중복 입력을 줄인다. 작성자 경계를 넘거나 기존 코드를 개인 실적으로 귀속시키지 않는다. 원본 근거와 인용 추적을 보존하며 안전하게 통합할 수 없으면 원본 diff로 분석한다. 동일한 근거·기준·모델·귀속 범위의 검증된 판정은 재사용할 수 있고 명시적인 전체 재분석은 새 판정을 요청한다. 입력 문자 수와 실제 API 토큰 사용량을 구분해 표시한다. 효율 수치는 점수 계산과 분리한다.

## 2026-09-28 링크 입력·진행 화면 개선

프로젝트의 Confluence·GitHub URL은 하나씩 추가 버튼/Enter로 등록하고 하단 목록에서 확인·제거한다. 복수 URL을 배열로 저장하며 모든 등록 범위의 근거를 수집·분석하고 겹치는 자료는 중복 처리하지 않는다. 진행 상황 조회는 변경된 진행률·문구만 갱신하고 화면 전체 재생성을 반복하지 않는다. 다른 화면으로 이동한 뒤 도착한 이전 조회 응답은 현재 화면을 덮어쓰지 않는다.

## 접근 실패의 격리와 진단

일부 근거 API가 409/403/404·연결 실패 등으로 접근되지 않아도 나머지 근거를 수집하여 평가를 완료한다. 실패한 경로·서비스·HTTP 코드·원인·조치를 진행 화면과 결과에서 확인한다. 빈 저장소 확인과 원인 미상의 409를 구분하고 비밀 정보는 반환하지 않는다. 접근되지 않은 자료 때문에 불완전한 점수는 잠정으로, 근거가 전혀 없는 항목은 판정 보류로 표시한다. 수집 불가를 감점 사유로 삼지 않는다. 원본 검증·LLM 검증 실패나 취소를 정상 완료로 가장하지 않는다.
